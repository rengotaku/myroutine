# ADR 0008: 要対応のコマンドを add_action の引数で受け取り、無ければ runner が要対応に積む

## 背景

#57 で要対応のコマンド行に色を付けた。色が付くのは、先頭の空白を除いて `→ $ ` か `$ ` で始まる行だけである。

要対応の本文は自由文で、この書き方は規約として決まっていなかった。2026-10-23 時点で、利用側の steps.d（darwin）にある
`add_action` の呼び出し 83 か所のうち 42 か所にはコマンド行が無かった。内訳は、コマンドが文中にあって行頭にないもの 10、
初期設定の不備（「〜を配置する」）18、「確認する」だけで何を打つか書いていないもの 11、人の画面操作 3。

成功の一言は ADR 0007 で規約を置き、runner が検査している。要対応の本文には同じ仕組みが無く、ステップを足すたびに
同じことが起きていた。

## 決定

1. `add_action <id> <本文> --cmd <コマンド> [--cmd <コマンド>...]` の形にする。prelude はコマンドを
   `      → $ <コマンド>` の行として本文の後ろに付ける。fd 3 のチャネルの書式は変えない（ADR 0006 の境界を保つ）
2. `--cmd` に値が無いとき、3 つ目以降に `--cmd` 以外の引数があるときは、`add_action` がエラーを返して要対応を積まない
3. runner は、ステップが出した要対応の 2 行目以降にコマンド行が無ければ、`<id>.__cmd` の要対応を積む。
   判定は描画と同じ `render.HasCommandLine` を使う。終了コードは変えず、dry-run では見ない。
   `MYROUTINE_ACTION_CHECK=0` で切れる（仮のステップを大量に使う統合テスト向け）
4. 実行されない分岐は 3 の検査に掛からない。steps.d を持つリポジトリの CI で、全ての `add_action` に `--cmd` が
   あるかを静的に検査する（この repo の外の話なので README で求めるにとどめる）

## 検討して捨てた案

- **ステップを Python などで書き直し、`Action(cmd: str)` を必須の項目にする**: 型検査が実行されない分岐まで見られる点は
  勝る。ただし、効いているのは「コマンドを別の項目として受け取る」ことで、言語ではない。引数にしてしまえば、静的検査は
  「`add_action` の呼び出しに `--cmd` があるか」を見るだけで済む。外部コマンドを呼ぶ処理は sh の方が短く書け、
  30 本以上の書き直しには見合わない（ADR 0001 / 0006 の判断も変えない）
- **本文の自由文を解析して、コマンド行が無ければ警告するだけにする**: 3 で実行時には拾えるが、静的検査が自由文の
  解析になり、複数行の本文や配列で組み立てた本文を正しく扱えない
- **`--cmd` を任意にする**: 「確認する」だけの要対応が残り続ける。画面操作しか無い場合も、開くためのコマンドは書ける

## 変えてよい前提 / 壊すと危ない前提

- 変えてよい: コマンド行の字下げ幅、`.__cmd` の文言
- 壊すと危ない: `HasCommandLine` と `WrapText` の判定は同じ規則でなければならない。検査が通ってもコマンド行として描画されない、
  という食い違いが起きる。1 行目は見出しなので、どちらも 2 行目以降だけを見る
