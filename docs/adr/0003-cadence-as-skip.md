# ADR 0003: 週次・月次の実行間隔を本体の skip として扱う

## 背景

毎日実行する前提のステップに混ざって、頻度を落としたいステップが出てきた
（重い brew upgrade、月 1 で十分な棚卸し、隔週金曜のスナップショット）。

## 決定

メタデータ `step_cadence`（`daily` / `weekly` / `biweekly` / `monthly`）と
`step_cadence_weekday`（`mon`..`sun` / `1`..`7`）を追加し、本体が前回成功日
（`$MYROUTINE_LOG_DIR/last-run/<slug>`）を見て、間隔を満たさない実行を
**既存の skip 経路**に落とす。

- 前回成功日は `ok` のときだけ更新する（dry-run は更新しない）
- 曜日指定は間隔より先に判定する（間隔を満たしていても指定曜日以外は実行しない）
- 番号を指定した実行（`myroutine 5`）は明示指定なので間隔判定をしない。
  全ステップ実行で一時的に無視したいときは `--force-cadence`

## 理由

skip は既に「実行して要対応の有無を評価できなかった」側として扱われており、
履歴の 4 列目（評価できた slug）にも載らない。間隔判定を skip に載せるだけで、
「今日は走らせない日」に前回の要対応が誤って解消扱いになる問題が構造的に起きない。

## 捨てた案

- **ステップ内で日付を見て早期 return する** — 「何もしなかった」が `ok` として
  記録され、履歴上は評価済みになる。要対応の解消判定と連続日数が汚れるうえ、
  ステップごとに同じ日付処理を書き写すことになる
- **週次用の別コマンド（`myroutine-weekly`）に分ける** — ステップ順・要対応サマリ・
  ログ・履歴が二重管理になる。頻度はステップの属性であって別の routine ではない
- **cron / launchd に週次ぶんを分離する** — 実行タイミングが手元の起動と無関係になり、
  「実行していない日」を要対応サマリから読み取れなくなる

## 変えてよい前提 / 壊すと危ない前提

- 変えてよい: 間隔の粒度（`Nd` のような任意日数を足す等）、曜日の表記
- 🔴 壊すと危ない: 間隔未達を **skip** として記録すること。`ok` に変えると
  履歴の「評価できた」定義が崩れ、要対応の解消・連続日数が誤る
- 🔴 壊すと危ない: 前回成功日の更新を `ok` かつ非 dry-run に限ること
